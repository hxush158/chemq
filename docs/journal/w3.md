  模型按它看到的资料拒答了 —— **模型没错，错在检索和我自己的标注**（第 4 步只标了一条，评测显示"排第 1"是假象）。

## 2. 我卡在哪、卡了多久、怎么出来的

- **AWS 账号**（卡了约 1.5 小时）：新版 builder 体验没有区域选择器、按国家分配 ap-southeast-2、MFA 在 Builder ID 页面、
  用 `aws login` 拿临时凭证 —— 和网上教程的老流程完全对不上。先按截图逐步核对"现在看到的是哪个页面"才理顺。
  boto3 要 ≥1.41 且装 CRT 扩展才读得了 `aws login` 的凭证。
- **`make seed` 把评测集写坏了两次**（卡了约 1 小时）：PGOPTIONS 进不了 docker 容器 → 先截断了 golden.jsonl 才报错；
  第一次修复在 SQL 前拼 `SET search_path`，psql 把 `SET` 也打印出来，每道题的答案多了一行 `{"v": "SET"}`。
  靠 `git status` 看到 golden.jsonl 被改了才发现。最后改成连接串里带 `options=-csearch_path`，并且先在内存里算完再原子替换文件。
- **中文 BM25 一开始等于没有**：PostgreSQL 的 `'simple'` 不切中文，整句变成一个词项。改成字二元组（bigram），
  写入用 `array_to_tsvector`，查询用 `::tsquery` 字面量 OR。
- ** 混合题"（既要查数又要解释原因）的处理** ：要考虑具体问题的处理顺序步骤，提示词不能产生误导

## 3. 重来一次我会怎么做

- 先做**只评检索**的评测，再做生成。这次顺序是对的：生成出问题时（K04）能立刻判断是检索的锅。
- 标注评测集时，把"答出这道题需要的**全部**依据"都标上，不只标最明显的那条。
- 给模型的提示只放**对外契约**，不放实现细节。DDL、内部表名、底层列名，模型看到就会用。
- 每改一条提示规则，连跑 3 次后**逐题**看有没有做过头，不只看总分。
- 预期先写下来再跑（这次做了：三条预期对了一条半），比跑完再解释有用得多。
