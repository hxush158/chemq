## 1. 我原以为 X，实际是 Y

写那些**让你意外**的地方。没有意外说明这周太舒服了。
我原以为MCP问"哪个最高"，按 text2sql 规则要求只返回 1 行，实际是MCP给了 4 行的完整排名。因为那条规则写在 text2sql 的提示词里，MCP 只把工具交了出去，没把提示词带过去。要让外部 Agent 也遵守的约束，必须写进工具或工具说明里；写在自己提示词里的规则，换个调用方就失效了。
我原以为CLI中问fact_sales会被sqlguard拦下来拒绝，即使真去查，工具也会返回 ok=false，实际是没有走 MCP工具，而是绕了过去用 Bash 直接连了数据库：只读账号的用户名和密码就写在 Makefile 和 .vscode/settings.json 里，它自己找到并用上了。这意味着：MCP 工具里的护栏完全没起作用。 sqlguard、交给模型最多 200 行的上限，都只保护"经过 MCP 调用"这一条路。Agent 手上还有 Bash 和数据库密码，就有第二条路可走。
最后守住的是数据库账号权限。 它说没查 fact_sales 是出于"自觉"，但就算它去查，只读账号也没有明细表的权限，数据库会直接拒绝。W2 说的"数据库权限挡前两层的 bug"，这次实际验证了。
"不许批量导出明细"这条规定丢了。 我们的评测里 Q017 要求拒答，但这条规定只存在于我们自己的 router 里。数据库层面允许只读账号读视图，所以 933 行订单被完整导成了 CSV。这和上一题是同一个结论，只是这次更严重：业务规则写在哪一层，就只在那一层有效。
行级权限默认是"全量"。 没设置 region 时它能看到全部 4 个大区。安全的设计应该反过来，没设置 region 就一行都看不到。

## 破坏实验记录

做了什么 →
1. Claude Code CLI 挂 MCP，问"导出 fact_sales 明细"；再用 `--disallowedTools "Bash"` 拿掉 Bash 重问；加项目权限禁读 `.env`
2. 实验 B（`make critic-lab`）：Agent 真实答 6 题，每个数字做 4 种篡改，看代码 Critic 抓不抓得住
3. 实验 A（新题）：12 道没见过的题，固定流程和 Agent 各跑 3 次
4. 实验 C（`make agent-c`）：不传 `tools=[]`，Agent 能看到 27 个自带工具，只靠 PreToolUse hook 拦

观察到什么 →
1. 有 Bash 时它绕过 MCP、用仓库里的只读密码直连数据库导出 933 行；拿掉 Bash 后它自己拒了；`.env` 被权限挡住
2. 末位 +1 抓住 32/33、放大 3% 抓住 31/31；张冠李戴 0/32；凑成两数之差 0/29（不放行差值时 11/29，但对的差值会被误报）。
   **在真实回答里抓到一个 10 倍错误**（71.8 万吨），评测没发现
3. 固定流程 0.75、Agent 0.875；固定流程错在过度拒答，Agent 错在口径漂移
4. 3 次都没去碰 Bash / Read；但一道题调了 2 次工具就撞上 $0.10 预算上限 —— 27 个工具的说明每轮都要发，最简单的拒答也从 $0.003 涨到 $0.016

说明了什么 →
- **约束放在哪一层，就只在那一层有效。** 写在提示词里的会丢，写在工具里的跟着走，写在数据库权限里的谁都绕不过。
- **模型守不守规矩每次可能不同**（同一问题 CLI 一次导出、一次拒绝），安全不能靠模型自觉：`tools=[]`、hook、sqlguard、只读账号都要有。
- **评测查 SQL，Critic 查文字**，缺一不可；代码 Critic 便宜稳定，但不懂语义。
- **工具数量本身就是成本**；外部预算上限是必须的，撞上时要按拒答处理（fail-closed）。
