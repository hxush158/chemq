## 1. 我原以为 X，实际是 Y

- 我原以为 SQL 越界检查可以完全用正则实现，实际要用 sqlglot 解析成 AST。
  `scripts/ast_vs_regex.py` 里正则放过了 UNION 越表、直接查明细表、`pg_catalog` 探测三种攻击，
  还把注释里带 "drop" 的正常 SQL 误杀了；AST 全部挡住。
- 我原以为测试结果不需要提示词引导，实际 text2sql 里要加输出约定。
  第一轮 6 道失败**没有一道是口径错**（`SUM(回款)/SUM(收入)` 一次都没写错），全是输出形状：
  没收敛到一行、月份格式、排序方向写反。
- 我原以为把 temperature 锁成 0 就能让评测稳定，实际新模型上这个参数已经删掉了（Sonnet 5 传非默认值返回 400）。
  同一份代码连跑三次，exec_acc 是 0.80 / 1.00 / 0.73。**单次总分不能用来判断改动好坏。**
- 我原以为「最近 6 个月」算错是 text2sql 的问题，实际错在 router：从 09 往前减了 6 得到 03，而 03~09 是 7 个月。
  更根本的是，text2sql 收到的 `QueryPlan` 里**根本没有原始问题**，「最低」「两个」这些决定 ASC / LIMIT 的词在 router 那一步就丢了。
- 我原以为拒答是 router 一层的事，实际每一层都要能拒答。`SqlCandidate` 没有拒答字段时，
  模型把拒绝写成了 `SELECT '查询被拒绝：…' AS 提示` —— 能过护栏、能执行、返回一行，被当成了答案。
  **schema 表达不了的东西，模型会塞进它能表达的地方。**
- 我原以为配了 RLS 策略就生效，实际视图默认以 owner 身份执行，而 owner 是超级用户，直接绕过 RLS。
  配置了 ≠ 生效了。

## 自测关卡

不看笔记，口述回答下面 5 个问题。答不上来的划在这里，下周开头补：

1. 为什么正则做 SQL 护栏不够？举两个能绕过的具体例子。
正则做SQL护栏只能处理简单的文本模式匹配，无法真正理解代码的“语义”。如UNION 拼接可以绕过SQL验证访问无权限的表，CTE子句中可以隐藏DELETE等危险操作

2. 扇出陷阱为什么比语法错误危险？你怎么在语义层消灭它？
扇出陷阱（Fan-out Trap）通常发生在在多表联接（JOIN）进行聚合计算时，其危险在于：SQL 语法合法，但执行结果错误，因为在JOIN时，笛卡尔积膨胀中间结果行数增加导致得到的值因为中间结果行数增加而成为错误值。在语义层面可以做先聚合，再联接”（Aggregate Before Join）或子查询隔离，在语义层定义建模规范时，禁止将两个处于“一对多”关系的子实体的度量在同一层级直接 JOIN。语义层引擎在编译生成 SQL 时，会自动将其拆分为多个独立的子查询（CUBE / CTE），在各自的粒度上完成聚合后再进行主键联接

3. 只读数据库账号已经挡住写操作了，为什么还要应用层的 sqlguard？
防止敏感数据泄露，以及充当强制上下文注入器

4. 用户问"上个月净利润多少"，系统里没有利润数据。正确行为是什么？错误行为有哪几种？
明确说"查不到"，然后停。说清楚答不了：refused=True，不返回任何数字，说清楚为什么：指标字典里没有这个指标
错误：编一个数、偷换指标、自己编口径等

5. 为什么权限过滤不能交给模型在 SQL 里加 WHERE？
无法防御 Prompt Injection（提示词注入攻击），容易漏查询条件
