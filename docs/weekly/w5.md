# W5 · 放到公网上，且账单可控

**能力目标**：第一次把 AI 服务真正部署到 AWS，并且知道钱会从哪些地方漏出去。

**达标线**：线上可访问（带认证），Budget 告警生效，AI 服务与网关职责分离清楚。

---

## 先说钱：2026 年的 AWS 免费套餐和你以为的不一样

**2025 年 7 月 15 日之后注册的账号**，规则变了：

- 没有"12 个月免费套餐"了（EC2 / RDS 750 小时那套已成历史）
- 改成：注册送 **$100 credits**，用服务再赚 **$100**，**6 个月或额度用完为止**
- **always-free 仍在**：Lambda、DynamoDB、S3、CloudWatch、SQS、SNS、Cognito、
  Step Functions、API Gateway、ECR 等 30+ 项

所以本项目的架构是 **always-free 打底 + credits 兜底**，数据库这周先不上云
（你选了本地 Docker 起步），W5 只把无状态层搬上去。

**开工前第一件事（不是最后一件）**：AWS Budgets 设一个 $10 的告警。

## 目标架构

```
浏览器/Postman
     │  Cognito JWT
     ▼
API Gateway (HTTP API)
     │
     ▼
.NET 网关 (Lambda)            ← 认证 / 数据权限 / 审计 / 限流 / 幂等
     │  X-Chemq-User, X-Chemq-Region
     ▼
Python AI 服务 (Lambda 容器镜像)  ← 编排与取数
     │
     ├──► PostgreSQL（W5 仍在本地 / 后续 Aurora Serverless v2）
     ├──► S3（知识库原文）
     ├──► DynamoDB（会话）
     └──► CloudWatch（日志 / 指标 / 成本埋点）
```

**为什么认证不放在 Python 服务里**：企业里认证/授权/审计通常已经有统一的一层，
AI 服务应该是**可替换的组件**，不是另起一套权限体系。这个回答在架构面试里很加分。

## 概念卡

**① serverless 冷启动**
Lambda 容器镜像首次调用要拉起容器。Python + 大依赖包可能 3–8 秒。
⚠️ 对问数这种交互式场景很致命。解法：provisioned concurrency（要钱）、瘦身镜像、
或者接受它并在前端做好 loading 提示。**先量它，再决定要不要治。**

**② IaC (CDK)**
基础设施写成代码。本项目用 **C# 版 CDK** —— 一份 .NET 技术栈，两处收益。
⚠️ 不要手点控制台。不是洁癖 —— 是你三周后想不起来自己点过什么。

**③ 最小权限 IAM**
Lambda 的执行角色只给它真正需要的权限。
⚠️ `*` 权限在演示项目里没人管，在面试里会被问。给自己养成习惯。

**④ Secrets Manager**
数据库密码、API key 不进代码库也不进环境变量明文。
⚠️ Secrets Manager 本身**不在 always-free 里**，每个 secret 约 $0.40/月。
Parameter Store SecureString 是免费替代品 —— 知道这个取舍就够了。

**⑤ 成本护栏**
Budgets（阈值告警）+ Cost Anomaly Detection（异常检测）+ 应用层的 token 计数。
⚠️ AWS 的账单有延迟（数小时）。**真正能实时拦住失控的是你应用里的 token 上限。**

**⑥ 可观测性**
结构化日志（structlog）+ CloudWatch Logs Insights + 自定义指标。
⚠️ 至少要能回答：这次问数花了多少钱？慢在哪一步？SQL 是什么？被护栏拦了吗？
→ 项目里：`qa_audit` 表就是为这个设计的

## 必做

1. **先建 Budget 告警**（$10），再写任何一行 IaC
2. .NET 网关：Cognito JWT 校验 → 解析 user/role → 映射到 region → 透传给 Python 服务
3. Python 服务打成 Lambda 容器镜像，推到 ECR
4. CDK (C#) 定义：API Gateway + 两个 Lambda + IAM 角色 + CloudWatch 告警
5. 端到端跑通：带 JWT 请求 → 拿到回答
6. 量一下冷启动时间，记在笔记里

## 加分

- Step Functions 做异步月报生成（问数是同步的，生成报告是异步的 —— 场景不同）
- 把 PostgreSQL 迁到 Aurora Serverless v2（最小 0 ACU 自动暂停），对比延迟变化

## 破坏实验 · 让账单失控（可控地）

**做什么**

1. **不设** token 上限，写一个循环调用 100 次问数，跑之前先估算成本
2. 看实际花了多少，和你的估算差多少
3. 把 Lambda 内存从 1024MB 改成 256MB，量执行时间和成本的变化
4. 故意让一个查询返回 10 万行（去掉 `max_rows`），看内存和延迟怎么爆
5. 在 CloudWatch 里找出这些事件 —— **你能在账单来之前发现它们吗？**

⚠️ 金额控制在几美元以内。目的是建立体感，不是真的烧钱。

**预期观察**

- 实际成本很可能比估算高（忘了算 cache_creation、忘了算重试）
- Lambda 内存调小**不一定省钱** —— 执行时间变长，可能反而更贵
- 10 万行会把内存和 token 一起打爆，而且失败得很难看

**说明了什么**

成本失控在云上是**无声的**。等账单来已经晚了几小时到几天。
真正的护栏必须在应用层：token 上限、行数上限、超时、并发上限。
AWS Budgets 是最后一道，不是第一道。
