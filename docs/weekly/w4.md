# W4 · 让它自己动：Agent 与工具

**能力目标**：能讲清 Client SDK / Agent SDK / Claude Code CLI 三者的边界，并说明各自什么时候用。

**达标线**：Q009/Q020 这类"既要数又要解释"的题端到端答对；Critic 能抓出注入的错误数字；单次复杂问答 < $0.05。

---

## 三件工具的边界（这是本周最值钱的一页）

| | 是什么 | 谁写 tool loop | 什么时候用 |
|---|---|---|---|
| **Client SDK** (`anthropic`) | 直接调 Messages API | **你自己写** | 流程确定、要精确控制每一步。W1/W2 就是它 |
| **Agent SDK** (`claude-agent-sdk`) | 把 Claude Code 当库用 | **SDK 替你跑** | 步骤不确定、需要模型自己规划。带 subagent / hooks / permissions / MCP |
| **Claude Code CLI** | 终端交互式 | SDK 跑 | 日常开发、一次性任务。可以挂你自己的 MCP server |

还有第四个：**Managed Agents** —— 长时间运行的 agent 托管在 Anthropic，你不用管沙箱和会话。
本项目用不到，但要知道它存在。

**一句话版本**：知道要做哪几步 → Client SDK；不知道要做哪几步 → Agent SDK；
想在终端里试试 → CLI。

## 概念卡

**① tool use**
你描述工具的 schema，模型决定什么时候调、传什么参数，你执行后把结果喂回去。
⚠️ 模型不执行任何东西，它只**生成调用请求**。执行永远是你的代码干的 —— 这也意味着
安全责任在你这边。

**② agent loop**
「想 → 调工具 → 看结果 → 再想」直到完成。
→ 项目里：Agent SDK 的 `async for message in query(...)`
⚠️ 循环的终止条件是模型自己判断"done"。所以必须有外部的 max turns / 超时 / 成本上限。

**③ subagent**
把子任务丢给独立上下文的 agent 做，只把结论带回来。
⚠️ 价值不在并行，在**上下文隔离**：主 agent 不会被子任务的一堆中间产物污染。

**④ MCP (Model Context Protocol)**
把"你的系统"接进"任意 agent"的标准插头。
→ 项目里：`mcp_server.py` 暴露 `list_metrics` / `run_semantic_query` / `search_knowledge`
⚠️ MCP server 里**同样要过 sqlguard**。不要因为"调用方是 Claude Code"就放松校验 ——
MCP 的调用方是可以换的。

**⑤ permissions vs hooks**
permissions = "能不能做"（事前，不可绕过）；hooks = "做了什么"（事中/事后，可记录可否决）。
⚠️ **不能互相替代**。只有 hooks = 全靠日志发现问题，来不及；只有 permissions = 不知道
agent 到底干了什么，出事无法复盘。审计要求高的场景两个都得有。

**⑥ Critic 模式**
独立一次调用，只核对数字，不评价文笔。
→ 项目里：`solutions/agents_w4.py` 的 `_critic()`
⚠️ 必须是**独立调用、不共享上下文**。同一次调用里让模型"自我检查"，
它会倾向于维护自己刚说过的话 —— 这是最常见的伪自检。

**⑦ 工具权限即职责边界**
Narrator 拿不到数据库工具，所以它物理上无法"再查一次把数据凑到叙述上"。
⚠️ prompt 里写"请不要自行查询"是**建议**；不给工具是**约束**。能用约束就别用建议。

## 破坏实验 · 让 Agent 选错工具、让 Critic 抓错

**实验 A：工具过载**

1. 给编排 agent 挂 15 个工具（把 `run_semantic_query` 拆成 `query_production`、
   `query_energy`、`query_sales`、`query_inventory`… 每个再分日/月/年版本）
2. 跑 W2 的评测题

**预期**：`exec_acc` 掉一截，而且失败模式变成"选了看起来最像的那个工具"。

**说明**：工具数量本身是成本。**工具选择是一个分类问题**，选项越多越难。
这正是 subagent 的价值 —— 不是并行，是每个 agent 面对的工具集更小。

**实验 B：往叙述里注入假数字**

1. 在 Narrator 的输出上手动改一个数字（比如把 74178.7 改成 78000）
2. 看 Critic 抓不抓得出来
3. 然后把 Critic 改成"和 Narrator 同一次调用里自检"，再试

**预期**：独立 Critic 能抓；同一次调用的自检大概率放过。

**说明**：自检必须有**对抗性**。共享上下文的自检是在验证"我说得通顺吗"，
不是"我说得对吗"。

**实验 C：关掉 permissions**

把 Narrator 的 `allowed_tools` 从 `[]` 改成 `["Read", "Bash"]`，问一个数据不足的问题。

**预期**：它可能去翻文件、跑命令来"补全"答案。

**说明**：能用工具权限约束的，不要写在 prompt 里靠自觉。
