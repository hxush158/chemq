# 6 周学习计划

## 这个计划的设计原则

**能力驱动，不是交付驱动。** 每周攻克一个概念簇，化工问数只是练习场。
系统能跑是副产品 —— 但它同时也是你的作品集和目标客户项目的原型，所以副产品也要做扎实。

**评测先行。** 评测集在 W1 就建起来，不是 W6。你无法改进你测不了的东西。
每周往评测集里加题、每周看分数怎么动，这是学习速度的主要来源。

**先坏后好。** 每周有一个"破坏实验"：故意把系统弄坏，观察它怎么坏。
看它怎么对，你只会记住结论；看它怎么坏，你才理解机制。

## 每周 9 小时怎么花

| 时段 | 时长 | 做什么 | 常见的坑 |
|---|---|---|---|
| 概念输入 | 90min | 读官方文档 + 本周概念卡。**不写代码** | 忍不住边读边写，结果两件事都没做好 |
| 动手实现 | 4×60min | 照验收标准写代码，跑评测 | 一口气写完再跑；应该写一点跑一点 |
| 破坏实验 | 90min | 按 `docs/weekly/wN.md` 做 | 跳过。这是全周信息密度最高的 90 分钟 |
| 复盘 | 60min | 写笔记 + 过自测关卡 | 写成流水账。模板里那三个问题才是重点 |
| Review | 60min | 让 Claude Code review 你的代码 | 让它替你写。见 `CLAUDE.md` |

**铁律：先自己写 30 分钟，再问 Claude。**

## 必做 vs 加分

54 小时装不下所有东西。每周的 `docs/weekly/wN.md` 里都分了两档：
**必做**是达标线，**加分**是时间有富余时做。砍加分项不影响下一周。
