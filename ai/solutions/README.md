# 参考实现

**使用纪律：先自己写满 30 分钟再翻这里。**

卡住的那 30 分钟才是学习发生的地方。直接看答案，你会觉得"都懂了"，
但两周后复现不出来 —— 这是识别错觉（recognition）冒充回忆（recall）的典型陷阱。

推荐的用法顺序：
1. 自己写，跑 `python ai/evals/run_eval.py --week N`，看分数
2. 分数不达标 -> 先看失败的题目，猜原因，改一版，再跑
3. 还是不行 -> 让 Claude Code **只给线索不给代码**：
   `"我的意图分类在 out_of_scope 这一类上总是漏，不要给我代码，给我三个可能的原因"`
4. 仍然卡住 -> 翻这里，但翻完之后把参考实现关掉，凭理解重写一遍

每份参考实现开头都有几个问题，看代码之前先回答它们。
那些问题才是这一周真正要学的东西 —— 代码只是它们的载体。
